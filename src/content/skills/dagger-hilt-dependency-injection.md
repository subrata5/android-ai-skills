# Dagger Hilt Dependency Injection

## The Situation

Manual dependency instantiation ("poor man's DI") leads to bloated Application classes, service locators with hidden runtime dependencies, memory leaks when references outlive their scope, and boilerplate setup code in every Activity and Fragment.

Dagger Hilt provides compile-time dependency injection tailored specifically for Android lifecycles. By leveraging Hilt's predefined components (`SingletonComponent`, `ActivityRetainedComponent`, `ViewModelComponent`, `ActivityComponent`), Android applications achieve strict lifetime management, compile-time validation of dependency graphs, and seamless test module substitution.

---

## Workflow

### 01 Module & Scope Definition

**Intent:** Bind implementation classes to interfaces with correct component lifetimes.

**Actions:**
* Use `@Module` and `@InstallIn(SingletonComponent::class)` for app-wide singletons (OkHttpClient, Room Database, Security keys).
* Use `@Binds` instead of `@Provides` when mapping interface contracts to concrete implementations (reduces generated bytecode size).
* Apply scopes (`@Singleton`, `@ViewModelScoped`) only when stateful lifecycle persistence is strictly required.

**Evidence:**
Interfaces are bound via abstract `@Binds` methods in dedicated Hilt modules.

```kotlin
// Example: Interface binding using @Binds in Hilt
@Module
@InstallIn(SingletonComponent::class)
abstract class RepositoryModule {

    @Binds
    @Singleton
    abstract fun bindUserRepository(
        impl: UserRepositoryImpl
    ): UserRepository
}
```

---

### 02 ViewModel Injection

**Intent:** Inject dependencies into ViewModels safely using `@HiltViewModel`.

**Actions:**
* Annotate ViewModels with `@HiltViewModel` and `@Inject constructor(...)`.
* Pass dependencies via constructor parameter lists without referencing `SavedStateHandle` directly unless state restoration is needed.
* In Jetpack Compose, acquire ViewModels using `hiltViewModel()` from `androidx.hilt.navigation.compose`.

**Evidence:**
Composable screens instantiate ViewModels cleanly via `viewModel: MyViewModel = hiltViewModel()`.

---

### 03 Test Replacement Modules

**Intent:** Swap production network/database bindings with mock/fake implementations during automated tests.

**Actions:**
* Use `@UninstallModules` in test classes to disable production modules.
* Bind test doubles using `@TestInstallIn`.
* Annotate test suites with `@HiltAndroidTest` and invoke `hiltRule.inject()` in test setup.

**Evidence:**
Instrumentation tests run against fast in-memory database mocks without touching live HTTP servers.

## Anti-Rationalization Gate

### Excuse
"I'll mark every provided object `@Singleton` so I don't have to think about component scoping."

### Rebuttal
Over-scoping objects as `@Singleton` prevents garbage collection, retains unused memory throughout the entire app process lifetime, and causes subtle state leakage between screen sessions. Apply scopes restrictively.

---

### Excuse
"I'll use `@Provides` for everything because `@Binds` syntax requires abstract classes."

### Rebuttal
`@Provides` generates extra factory classes and method invocations in bytecode. `@Binds` generates direct assignments, reducing APK size and compile-time annotation processing overhead.

---

## Red Flags

* Direct instantiation of Repositories or UseCases with `new` or `Constructor()` inside ViewModels or Composables.
* Using ServiceLocator patterns (`MyApplication.instance.getComponent()`) inside UI logic.
* Injecting Android `Context` into domain UseCases or singleton singletons without using `@ApplicationContext`.
* Dynamic casting of `Application` or `Activity` to custom DI interface containers.

---

## Verification

1. **Hilt Compile Verification:** Run `./gradlew compileDebugKotlin` to verify DAG validation succeeds at compile time without circular dependencies.
2. **Hilt Test Execution:** Run `./gradlew connectedCheck` with `@HiltAndroidTest` suites verifying test replacements.

---

## Exit Criteria

* [ ] Hilt configured in Application class with `@HiltAndroidApp`.
* [ ] All ViewModels use `@HiltViewModel` injection.
* [ ] Interface bindings use `@Binds` where applicable.
* [ ] Scopes are restricted to necessary lifecycle components.
* [ ] Automated tests use `@HiltAndroidTest` module substitution.
