I prefer learning technology by understanding:

**What it is → Why it exists → How it works internally → When to use it → When NOT to use it → How it behaves in production.**

For example, when learning Android Coroutines, I am interested not only in using `suspend`, but also in understanding:

- Coroutine execution
- Dispatchers
- Structured concurrency
- Cancellation
- Coroutine scopes
- Exception propagation
- Threading
- Context switching
- Lifecycle integration
- Production failure scenarios

The same philosophy applies to architecture, Compose, Android internals, AOSP, AI agents, and system design.
